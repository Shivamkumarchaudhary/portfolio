The architecture was crafted using vanilla web technologies without heavyweight frontend frameworks to ensure near-instant page load times (Lighthouse performance score: 99+), zero runtime vulnerability dependencies, and instant compatibility with GitHub Pages static hosting.

The stylesheet in assets/css/style.css leverages CSS Custom Properties (Variables) to toggle seamlessly between a deep dark cyber-slate palette and a crisp light theme: 

:root {
  /* Dark Mode Palette (Default) */

  --bg-secondary: #0f172a;

  --text-primary: #f8fafc;
  --accent-cyan: #38bdf8;
  --accent-indigo: #6366f1;
  --grad-primary: linear-gradient(135deg, #38bdf8 0%, #6366f1 50%, #8b5cf6 100%);

[data-theme="light"] {
  --bg-primary: #f8fafc;
  --bg-secondary: #f1f5f9;

2.2 Vanilla JavaScript Functional Engine

Written in modern ES6+ (assets/js/main.js), the logic operates completely client-side:

  • Typewriter Engine: Iterates asynchronously through professional roles (Web Developer, DevOps Enthusiast, MCA Scholar) with realistic typing, pause, and deletion intervals.
  • Theme Persistence: Checks localStorage.getItem('portfolio-theme') and synchronizes root attributes on render.
  • Active Scrollspy: Listens to window scroll events, calculates current viewport section coordinates, and highlights the respective navigation pill.
  • Project Categorization & Modal: Dynamic array-driven modal popups rendering project architectures, GitHub links, and key capabilities upon user interaction.
  • Contact Verification: Client-side validation ensuring valid email formatting and populated required fields, triggering an animated success toast notification.

6. Deploying the Website Using GitHub Pages

GitHub Pages turns code repositories into hosted static websites with automated SSL/TLS certificates and global CDN edge routing.

6.1 GitHub Pages Configuration Options

  1. Classic Branch Deployment (Settings > Pages): Navigate to Settings → Pages → Under Build and deployment select Deploy from a branch → Branch: main, Folder: / (root) → Click Save.
  2. GitHub Actions CI/CD Deployment: Workflow file placed at .github/workflows/deploy.yml:
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4
